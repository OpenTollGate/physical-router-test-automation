# FIPS exit guard: one isolated packet lane

Run from this repository as an ordinary user (not with `python -O`):

```sh
TMPDIR="$HOME/.hermes/profiles/manager/cache/scratch" \
python3 scripts/fips-exit-packet-lane.py \
  --module-repo "$HOME/worktrees/tollgate-fips-exit-consumer"
```

Requires Linux, noninteractive sudo permission for unshare, mount/network
namespaces, iproute2, nft, ping, Python 3.10+, Git and Go 1.22+.
Missing privileges/tools fail nonzero: no simulated pass or skipped kernel lane.
`/run/netns` must already exist. No hardware, router leases or payments are used.

## Provenance and reuse

Base inspected/fetched before edits: upstream OpenTollGate PRTA main `530aa43`.
Inspected `lib/netns_probe.py`, `scripts/0.6.0-validation/tg-lib.sh`,
`alpha-quicktest.sh`, and `hwsim-netns-poc.py`. The first helpers move physical
NICs or attach to host bridges; they are inappropriate here. This lane reuses
**the existing hwsim Runner.run/ns command runner**, overriding only cleanup
so it neither operates radios nor unloads kernel modules. No second framework.

Renderer pin: `b2e4f615cff9fa369eb3918406be7d559001f9ad`.
The lane reads `address.go`, `config.go`, `render.go` directly from those Git
objects into a disposable standalone Go fixture, compiles their unchanged
bytes, calls real `RenderFW4`, and records the SHA256 of its returned fragment.
It does not use a copied nft rules fixture or modify the module checkout.
The standalone fixture module directive is Go 1.22 (these three dependency-free
files compile on it); this is not a build of the entire module application.
Fixture public keys are `[32]byte{1}` and `[32]byte{2}`, MTU 1240,
interfaces `guest-test`, `mesh-test`, `exit-test`, table 200/priority 10000.

## Containment and topology

The launcher first enters a **privileged outer network AND private mount
namespace**. Before mutation the child verifies distinct namespace identities
and that the outer network contains only loopback. A private tmpfs at
`/run/netns` contains all named-netns mounts. All veth creation, routing,
forwarding sysctl and nft operations occur inside this boundary. Nothing is
attached to a host NIC or host bridge; no host routes/firewall are changed.

Four veth links connect consumer to guest, tunnel-peer, WAN and non-guest
endpoint: `10.73.{1,2,3,4}.0/24`, consumer `.1`, endpoints `.2`.
`exit-test` is intentionally **a plain veth**, not an actual tunnel. The consumer
also owns derived inner `100.65.208.250/32`. Endpoint default routes return via
consumer. No external networking is required.

Cleanup runs in `finally` (also after SIGTERM/KeyboardInterrupt), deletes the
five named namespaces and checks the private registry is empty. The outer
namespace also dies on process exit. An initial real execution hit an nft
syntax error in the *observation fixture*, exited nonzero, and printed the empty
registry cleanup confirmation; that syntax was fixed before the successful run.

## Packet assertions and measured evidence

[`evidence/fips-exit-simple-veth.log`](evidence/fips-exit-simple-veth.log)
records a real exit-0 run on 2026-11-25, nft 1.0.9. Fragment SHA256:
`6698227e8f5bc49a1741c5654a044ce930ae48bc405c7eb474800caf7b232b3a`.

The same exact renderer output is wrapped only in `table inet fw4` and the
caller-owned portal define. ICMP echo/reply probes exercise the kernel:

| Probe | Guard absent | Guard enabled (twice) |
|---|---|---|
| guest → WAN | reply | timeout; guard drop counter +1 |
| peer → consumer INPUT | reply | timeout; guard drop counter +1 |
| peer → non-guest endpoint | reply | timeout; guard drop counter +1 |
| peer → guest unsolicited | reply | timeout; guard drop counter +1 |
| guest → peer → guest established return | — | reply; later established-return counter +1 |

Sequence is absent → enabled → removed → re-enabled: removal makes every
blocked probe succeed, re-enable makes each fail again. This is the negative
control/RED-to-GREEN contract, not a string assertion. Ping operational errors
are failures, not interpreted as filtering. JSON ruleset dumps retain individual
rule counters; the assertion reads per-chain counter deltas. A separate
priority -1 observation hook counts actual established returns after the -2
guard; it changes no generated bytes and supplies no authorization bypass.

## Deliberate limits / next lane

This proves only the generated guard's IPv4 behavior with simple interfaces.
It is **not full fw4/NDS interoperability**, FIPS transport, a paid service,
IPv6 suppression coverage, TCP MSS validation, or an ipip6 dataplane result.
No NDS/authorization gate is installed; guard return/policy accept merely permits
continued processing. Next: replace the veth tunnel leg with real ipip6 over an
isolated IPv6 underlay, then exercise the real NDS/fw4 hook ordering with both
unauthorized and authorized guest traffic and established returns. Keep those
claims separate from this small lane.
